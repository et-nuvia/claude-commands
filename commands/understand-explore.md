You are the executor for `/understand-explore`. The script is **read-only** — it never writes or modifies any file.

## Tracking

> Output format is auto-detected (TOON for AI callers, JSON for CI/scripts). Use `--toon` or `--json` to override.

As your **first action**, before any other work, run:
```bash
~/.claude/scripts/track-command.sh --command "understand-explore" --event start
```

If the workflow encounters an unrecoverable error at any point, run:
```bash
~/.claude/scripts/track-command.sh --command "understand-explore" --event error \
  --model "MODEL_ID" \
  --error-msg "brief description of what failed"
```

## Execute

Pass the user's chosen subcommand and arguments directly to the script:

```bash
# --search: ranked keyword match on node id / name / summary
RESULT=$(~/.claude/scripts/understand-explore.sh --json --search "router middleware")

# --node: one node + 1-hop neighbors
RESULT=$(~/.claude/scripts/understand-explore.sh --json --node "src/api/router.py")

# --tour: dependency-ordered walk (leaves first), optional --limit N
RESULT=$(~/.claude/scripts/understand-explore.sh --json --tour --limit 20)

# --for-task: rank nodes by keyword overlap with task TSK/PLN docs
RESULT=$(~/.claude/scripts/understand-explore.sh --json --for-task 293A14)

# --stats: graph metadata, counts, layer distribution, staleness
RESULT=$(~/.claude/scripts/understand-explore.sh --json --stats)
```

Script automatically:
- Locates `.understand/graph.json` in the repo root
- Validates graph JSON and schema version
- Returns structured results with a `status` field (`"success"` or `"error"`)

## Response Handling

Read `status` from `RESULT` and proceed:

**`"success"` from `--search`** — Present the `results[]` array to the user as a ranked list. Each entry has `id`, `name`, `summary`, and `score`. If empty, say no nodes matched the query.

**`"success"` from `--node`** — Show the node's `id`, `summary`, and `layer`, then list incoming and outgoing edges with their types. Summarize what the node does and how it connects.

**`"success"` from `--tour`** — Walk the `nodes[]` array in order (leaf dependencies first). Briefly describe each node's role and its position in the dependency chain. Note total count and any truncation from `--limit`.

**`"success"` from `--for-task`** — Show the ranked `nodes[]` with their overlap scores. Explain which files are most relevant to the task and why (based on matched keywords). If `message` indicates no task docs found, report it to the user and suggest running `/understand-scan`.

**`"success"` from `--stats`** — Report `node_count`, `edge_count`, `layer_count`, `scanned_at`, and the `layer_distribution` breakdown. Note if the graph is stale (older than a day).

**`"error"`** — Surface the `message` field to the user. Common causes:
- Graph not found → run `/understand-scan` first
- Incompatible schema version → re-run `/understand-scan` to migrate
- Missing required argument (`--search` needs a query, `--node` needs an id, `--for-task` needs a task id)

## Completion Tracking

When the workflow completes successfully, run:
```bash
~/.claude/scripts/track-command.sh --command "understand-explore" --event complete \
  --model "MODEL_ID" \
  --complexity COMPLEXITY \
  --tokens TOKENS_ESTIMATED \
  --cost COST_ESTIMATED
```

Replace values before calling:
- `MODEL_ID` — the model currently in use (from system context, e.g., `claude-sonnet-4-6`)
- `COMPLEXITY` — 1-5 based on: 1=read-only analysis, 2=single-file/simple git, 3=multi-file feature,
  4=cross-system/staging deploy, 5=production/infrastructure/security
- `TOKENS_ESTIMATED` — rough estimate of context used (input + output tokens combined)
- `COST_ESTIMATED` — approximate cost in USD based on model pricing

## Debugging

~/.claude/scripts/understand-explore.sh --raw --search "query"
